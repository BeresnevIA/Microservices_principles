Задание 1

Предложите решение для обеспечения реализации API Gateway. Составьте сравнительную таблицу возможностей различных программных решений. На основе таблицы сделайте выбор решения.

Решение должно соответствовать следующим требованиям:
- маршрутизация запросов к нужному сервису на основе конфигурации,
- возможность проверки аутентификационной информации в запросах,
- обеспечение терминации HTTPS.

Обоснуйте свой выбор.

Задание 2 

Составьте таблицу возможностей различных брокеров сообщений. На основе таблицы сделайте обоснованный выбор решения.

Решение должно соответствовать следующим требованиям:
- поддержка кластеризации для обеспечения надёжности,
- хранение сообщений на диске в процессе доставки,
- высокая скорость работы,
- поддержка различных форматов сообщений,
- разделение прав доступа к различным потокам сообщений,
- простота эксплуатации.

Обоснуйте свой выбор.

### Выбор решения: NGINX

**Обоснование:**

1. **Высокая производительность** — NGINX является одним из самых быстрых обратных прокси, что критично для API Gateway
2. **Простота настройки** — конфигурация на основе файлов, понятный синтаксис
3. **Надёжность** — проверенное временем решение, используется в крупнейших проектах
4. **Гибкая аутентификация** — поддержка модуля `auth_request` для проверки токенов
5. **Отличная поддержка HTTPS** — полноценная терминация SSL/TLS
6. **Бесплатность** — Open Source решение без лицензионных ограничений
7. **Широкое сообщество** — множество готовых решений и примеров

### Выбор решения: Apache Kafka

**Обоснование:**

1. **Высокая надёжность** — отличная кластеризация с репликацией данных
2. **Долговременное хранение** — все сообщения сохраняются на диске с возможностью перечитывания
3. **Максимальная производительность** — высокая пропускная способность (миллионы сообщений/сек)
4. **Гибкость форматов** — работает с любыми бинарными данными
5. **Тонкая настройка прав** — детальная ACL система с разделением по топикам
6. **Exactly-once гарантия** — поддержка exactly-once семантики для критичных данных
7. **Масштабируемость** — легко масштабируется горизонтально

**Альтернатива:** Если требуется более простое решение, можно выбрать **RabbitMQ** — он проще в эксплуатации и имеет отличную поддержку различных протоколов.
